# 04 · 排错

按顺序查，别跳。每一条都对应一个真的踩过的坑。

## 1. 「登录掉了」

```bash
node scripts/bili-auth.mjs; echo "exit=$?"
```

| 退出码 | 结论 |
|---|---|
| 1（`-101`） | 真掉了，重新扫码 |
| 2（`-352` / `-403` / 网络） | **不是掉线**，是风控或网络；放慢节奏等一会儿 |

最常见的误判：把 `-352` 当成掉线，白扫一次码。

## 2. 取数一直报错

- `-403`：空间接口对脚本很吝啬。脚本会自动退到搜索接口，如果两条都失败，先降频
- `-412`：请求太密。停几分钟
- 签名错（`-352` 里也有这一种）：`wbi` 那两个 key 是从 `/x/web-interface/nav` 现取的，**取不到时不能拿旧的硬顶**，否则签名全错

## 3. 插件报 `no key`

三个可能，按可能性排：

1. `~/.dsh/asr.json` 的 `baseUrl` 指到了外网地址（本机地址不需要 key）
2. 那一层 `speechToText` 服务没注册上
3. 配置文件根本不存在——插件会老实报 `no key`

```bash
curl -s http://127.0.0.1:8123/health   # {"ok":true} 就说明服务活着
```

## 4. 转写没有分段 / 台词全挤在一格里

- 服务端没返回 `segments`（按契约，必须给）
- `segments` 用了绝对时间，不是相对本次上传的 0 起点

对了之后**清一下插件对同一个文件的缓存**再试——插件会缓存转录，改完配置还看到老结果，多半是缓存没失效。

## 5. 起不来：`EADDRINUSE`

上一份服务没退干净。要么等 `idleMs` 到了它自己退，要么换个端口：

```bash
ASR_PORT=8124 node scripts/asr-server.cjs
```
（改完记得同步 `asr.json` 的 `baseUrl`）

## 6. 下载那步偶发 SSL 握手失败

重试一次就过，不是参数错。这种事别急着改代码。

## 7. 拼图读不出字

- 快剪合集在 `compact` 下只剩骨架 → 单独 `video_zoom`
- 字幕在画面里但 ASR 认不出（歌、混音）→ `video_subtitles` 切字幕带
- 格子太小 → 别整片换 `full`（更贵），只对那一小段 `zoom`

## 8. 结果和上一次对不上

先问两个问题，再改代码：

1. **这个结论是什么时候的？**（版本、缓存、风控状态都会变）
2. **它全不全？**（抽样、翻页翻完了没有）

看起来很硬的证据，先对一遍时间戳和覆盖范围，再拿来说话。
