# 02 · B 站登录与取数

插件只会读你给它的链接或文件。要让「给链接」这件事成立，需要两样：**能取到片子信息的登录态**，和**能自己找片子的入口**。

## 1. cookie 怎么放

```bash
mkdir -p ~/.dsh/worlds/default/room/cookies
```

```
~/.dsh/worlds/default/room/cookies/
  bilibili-login.txt   必需。扫码登录后导出的 Netscape 格式 cookie
  bilibili.txt         可选。更早的一份，认证多半已过期（-101），只要它的匿名设备号
```

格式是 Netscape 那套，一行一个 cookie、制表符分隔：

```
# domain        includeSubdomains  path  secure  expire       name  value
.bilibili.com   TRUE               /     FALSE   0            SESSDATA  xxx
```

`bili-cookie.mjs` 的合并规则，一句话就够了：

> **认证字段（`SESSDATA` / `bili_jct` / `DedeUserID`）以 `bilibili-login.txt` 为准；设备号（`buvid3` / `buvid4` / `_uuid` / `b_nut`）缺了才从旧文件补；同名一律不覆盖。**

文件放别处也行：

```bash
export BILI_COOKIE_DIR=/somewhere/cookies
```

## 2. 查登录态（有语义的退出码）

```bash
node scripts/bili-auth.mjs
```

| 退出码 | 输出 | 含义 | 该做什么 |
|---|---|---|---|
| 0 | `登录着：<昵称> mid=<数字>` | 正常 | 无 |
| 1 | `掉了：-101 …` | **才真叫掉线** | 重新扫码 |
| 2 | `不确定：code=-352 …` | 风控/网络，不是掉线 | 等几分钟放慢节奏，别急着扫码 |

分不清 `-101` 和 `-352`，最直接的后果是：明明只是被风控限速，却让人去重扫一次码。

## 3. 看某个 UP 主最近发了什么

```bash
node scripts/bili-up.mjs
```

策略是「两条路」，因为 B 站的空间接口对脚本很不友好：

1. 先走**空间投稿接口**
2. 被风控挡了（常直接 `-403`，连点几下就 `-352`）就自动退到**搜索接口**：`search_type=video&order=pubdate&keyword=<账号名>`，翻几页，再按 `author` 精确筛回这个号

节流是自己加的，别省：请求之间留 1.5 秒，两个号之间留 2 秒。连点会把自己打成 `-412`。

## 4. 搜索

```bash
node scripts/bili-search.mjs "关键词"
```

B 站搜索要 **wbi 签名**：

1. `GET /x/web-interface/nav` 拿 `wbi_img.img_url` 和 `sub_url`
2. 从两个 URL 里取文件名（去掉目录和扩展名）当 `imgKey` / `subKey`
3. 拼起来，按固定的 `mixinKeyEncTab`（64 个下标的置换表）重排，取前 32 位
4. 参数按 key 排序 → 拼成 query → 末尾加 `wts=<秒级时间戳>` → 算 MD5 当 `w_rid`

`bili-search.mjs` 和 `bili-up.mjs` 里各有一份同样的实现。**改一边要改另一边**，否则两个脚本会开始给出不一样的结果，还都「看起来正常」。

## 5. 一条片子的简介、数据、评论

官方 web 接口，带登录 cookie 就够，不用签名：

```js
// 简介 + 计数
GET https://api.bilibili.com/x/web-interface/view?bvid=BVxxxx
//   data.title / data.desc / data.stat.view / data.stat.reply / data.aid

// 评论：type=1 是视频，oid 用上面拿到的 aid
GET https://api.bilibili.com/x/v2/reply?type=1&oid=<aid>&sort=2&ps=20&pn=1
//   data.replies[].content.message
```

实测（2026-11-16，一条 6 万播放的片子）：`view` 返回 `code:0`，标题、简介、播放数、评论数、`aid` 全有；`reply` 返回 `code:0`，正文可读。

拿到 `desc` 和 `replies` 之后，才谈得上「读一条片子」——只解画面和音轨，等于永远只看了一半。
