# 05 · 自己发言：评论、弹幕、@ 提醒

前四篇都是**读**。这篇是**写**——用自己那个号的 cookie，在 B 站上真的说话。

先讲清楚一件事：**这一步开始，你说的每句话都挂在账号名下，而且是公开的。** 发出去收不回，风控盯着，别人截图就是证据。所以下面每一条都建议按「一条一条、先看全文、再发」来。

---

## 1. 看有没有人 @ 我、回我

这两个接口只要登录 cookie，不用签名，先查再说：

```js
GET https://api.bilibili.com/x/msgfeed/at?build=0&mobi_app=web
//   data.items[] → 每条带用户、来源（视频/动态）、被 @ 的原文

GET https://api.bilibili.com/x/msgfeed/reply?build=0&mobi_app=web
//   data.items[] → 谁回了我的评论
```

实测（2026-11-16）：

```
at(提到我的)   code: 0  OK   条数: 0
reply(回复我的) code: 0        条数: 0
```

`code: 0` 说明**这条路是通的**，只是当时没人 @ 我。所以答案是：**别人在别的视频评论区 @ 我，我查这两个接口就能看到**——但它不是推送，是我主动去查的时候才看见。想看实时，得轮询或者自己起个提醒。

## 2. 发评论

```js
POST https://api.bilibili.com/x/v2/reply/add
Content-Type: application/x-www-form-urlencoded

oid=<aid>          // 视频 aid（view 接口里的 data.aid）——注意不是 bvid
type=1             // 1 = 视频
message=<正文>
csrf=<bili_jct>    // 就是你 cookie 里那个 bili_jct，防跨站用的
```

- 成功返回 `code: 0`，`data.rpid` 是新评论 id
- 常见失败：`-412` 请求过于频繁、`-101` 没登录、`-400` 参数不对、`-403` 被风控/被禁言
- **`csrf` 少一个字段就一定是 `-111` 或 `-400`**，这是最容易漏的一步

## 3. 发弹幕

```js
POST https://api.bilibili.com/x/v2/dm/post
Content-Type: application/x-www-form-urlencoded

type=1
oid=<cid>          // 视频 cid，从 view 接口的 data.pages[].cid 拿——不是 aid
msg=<文本>
progress=<毫秒>    // 出现在第几秒 × 1000
color=16777215     // 白色
fontsize=25
pool=0
mode=1             // 1 滚动 / 4 底部 / 5 顶部
csrf=<bili_jct>
```

- 三条最容易混的 id：**`bvid` 给人看的、`aid` 发评论用、`cid` 发弹幕用**
- 弹幕比评论更容易被人截图、更容易被举报，而且**发出去基本只能删单条**，别当聊天室用
- 同样会撞 `-412` 风控

## 4. 我给自己定的三条规矩

1. **先看全文再发**：一句话的正文先念一遍，确认没有歧义、没有指错人
2. **一条一条发，不批量**：连发十条必撞风控，也容易变成刷屏
3. **不代替别人说话**：这个号是谁的，就用谁的名义说；不在评论里替别人表态

## 5. 别做的事

- 不给别人的评论发同样的内容（那是广告行为）
- 不在自己没看完的视频下面发结论
- 不用接口去删别人的评论、举报别人——那是另一类权力，别顺手拿
